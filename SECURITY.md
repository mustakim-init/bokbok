# Security Policy

Thank you for caring about the security of bokbok-v2. Please follow the instructions below to report vulnerabilities privately so we can fix them before public disclosure.

## How to report a vulnerability
Preferred method:

- Open a private GitHub Security Advisory for this repository (recommended).
- Or email me. E-mail: [mioact2smart@gmail.com]

## Reporting a Vulnerability

Title:
- Short, descriptive title (e.g., "SQL injection in login endpoint")

Affected component(s):
- Product/repo: bokbok-v2
- Version/branch/commit: (e.g., v2.1.0, master, commit SHA)
- OS/environment (if relevant)

Severity (your estimate):
- Low / Medium / High / Critical — briefly justify

Summary:
- One-sentence summary of the vulnerability and impact

Impact:
- What an attacker can achieve (e.g., data exfiltration, RCE, privilege escalation)
- What data or users are affected

Reproduction steps (exact and minimal):
1. Preconditions (authentication, configuration)
2. Step 1
3. Step 2
4. ...
- Expected result
- Actual result

Proof of Concept (PoC):
- Paste minimal PoC code, curl commands, or a link to an encrypted attachment
- If attaching files, list filenames and brief descriptions

Exploitability / Complexity:
- How easy is it to exploit? (e.g., unauthenticated, requires user interaction, local-only)
- Any required privileges

Temporary mitigations / workarounds:
- Steps to reduce risk until a patch is available

Suggested fix (if known):
- High-level recommendation or code hint (if applicable)

Third-party dependencies involved (if any):
- Dependency name and version
- Whether issue is upstream

Sensitive data included?
- Indicate if the report contains secrets, PII, or private keys
- If yes, please encrypt using our PGP key or submit via private GitHub Security Advisory

Disclosure preference:
- Coordinate disclosure with maintainers (recommended)
- Public disclosure allowed immediately
- Request anonymity / do not credit

Contact information:
- Name / handle:
- Email:
- PGP key fingerprint (optional, for encrypted replies)
- Best time/method to reach you

Additional notes / references:
- Any CVE requests, related issues, or links to research

Thank you — include any files or logs as attachments or encrypted content when submitting.
